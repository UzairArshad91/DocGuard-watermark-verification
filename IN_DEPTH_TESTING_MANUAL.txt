============================================================
6. CORE FUNCTION TESTING
============================================================

hashing.py
- Hash the same file twice; hashes must match.
- Modify one byte; the hash must change.
- verify_hash with the correct hash should return True.
- verify_hash with a wrong hash should return False.
- Missing files should raise an error.

Example:

from hashing import get_file_hash, verify_hash
hash_value = get_file_hash("test.docx")
print(verify_hash("test.docx", hash_value))

Expected:

True

encrypt.py

from encrypt import encrypt_id, decrypt_id
token = encrypt_id(123)
print(decrypt_id(token))

Expected decrypted value:

123

Also test corrupted tokens and invalid tokens.

dlp_utils.py

from dlp_utils import is_verified_recipient, is_blocked_upload
print(is_verified_recipient("ea16826@gmail.com"))
print(is_verified_recipient("unknown@example.com"))
print(is_blocked_upload("https://chat.openai.com/upload"))
print(is_blocked_upload("https://company-portal.com"))

Expected:

True
False
True
False

Test uppercase, partial domains, empty strings, and malformed URLs.

watermarking.py
For each DOCX, XLSX, and PDF:
1. Record the original file hash.
2. Add a watermark.
3. Confirm the file remains readable.
4. Confirm the visible watermark exists.
5. Confirm signature metadata exists.
6. Generate the signature hash.
7. Modify the file.
8. Confirm the signature hash changes.

DOCX: inspect the footer and core properties.
XLSX: inspect the A1 comment and workbook description.
PDF: inspect annotations and /Signature metadata.

employee.py - send_document()
Test:
- Empty path.
- Missing file.
- Empty recipient.
- Empty PIN.
- Unknown user.
- Wrong PIN.
- Unverified recipient.
- Valid DOCX.

Verify that failures are reported and successful sends create database rows.

============================================================
11. ISSUES TO WATCH DURING TESTING
============================================================

- encrypt.py generates a new key whenever the process starts, so old tokens
  may not decrypt after a restart.
- send_document() does not check HTTP response status codes.
- send_document() logs user_id as doc_id instead of using the document ID
  returned by /send.
- Resend testing requires RESEND_API_KEY.
- Duplicate emails may cause a database exception.
- gui.py uses hard-coded user ID 1.
- file_watcher.py monitors files in the project folder.
- restart.bat terminates all python.exe and pythonw.exe processes, not only
  this application.

Record every test as PASS, FAIL, or BLOCKED. For failures, record the exact
error message, the steps used, and the document or account involved.
